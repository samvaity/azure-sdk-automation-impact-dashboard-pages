Per-architect interaction data

Automation routing and completed review work are separate interactions. A routing selection does not mean that architect completed the review; signoff credit belongs only to the person who applied the valid signoff.

Automation routing selection: an individual review request created by azure-sdk-automation within 24 hours of data-plane-review-requested. It measures routing, not completed review work. Team requests, CODEOWNERS, manual requests, and later assignments are not included.
Valid signoffs applied: human applications of data-plane-review-signoff. A signoff is excluded when azure-sdk-automation removes it within two minutes, which is the operational rejection rule used by this report.
Median elapsed request-to-signoff: wall-clock time from the review-request label to a valid signoff. It includes waiting, PR changes, and coordination; it is not architect effort or time saved. Each value includes its completed sample count as n.

What can be learned

Workload distribution

Assignments and open work show whether review demand is concentrated and where balancing or additional coverage may help.

Waiting patterns

Request-to-signoff timing can identify review paths worth examining, but it includes service-team responses, PR readiness, and review complexity.

Automation opportunities

Repeatedly slow paths can be inspected for missing context, manual coordination, or routine checks that automation could prepare earlier.

Evidence limits

GitHub events measure workflow elapsed time, not cognitive effort. This page links the PRs that support displayed counts, but it does not publish raw event payloads, comments, tokens, or private telemetry.

Public architect evidence extension. Handles are plain text and do not create GitHub mentions.
